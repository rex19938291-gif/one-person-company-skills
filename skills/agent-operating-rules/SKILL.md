# 代理工作規範（agent-operating-rules）

## 這個 skill 在解決什麼

一個人帶著好幾個代理做事，最常出事的不是程式寫錯，而是：換了代理就重做一遍、要人決定的事沉在聊天裡沒人看到、刪了不該刪的東西、執行者說「做完了」其實沒驗。這份規範把這些坑變成每回合都會讀到的規則，寫進代理的全域設定。

本 skill 只有文件，沒有任何可執行腳本。它不會連網、不會改權限或 hook，也不會自動執行；所有寫入都要你在卡片上點同意。

## 檔案

| 檔案 | 用途 |
|---|---|
| `rules/core-rules.md` | 寫進全域設定的規範本文（兩種代理共用） |
| `rules/adapter-claude-code.md` | 只有 Claude Code 才需要的差異 |
| `rules/adapter-codex.md` | 只有 Codex 才需要的差異 |
| `templates/TASK_HANDOFF.md` | 專案交接檔範本 |
| `templates/待決策佇列.md` | 專案待決策佇列範本 |
| `docs/skill-dependencies.md` | 其他 skill 怎麼標示依賴本規範，以及與廣告類 skill 的互動 |

## 安裝流程（寫入全域設定屬高風險，每一步都要照做）

### 1. 偵測代理

- Claude Code：目標檔 `~/.claude/CLAUDE.md`，內容＝`rules/core-rules.md`＋`rules/adapter-claude-code.md`。
- Codex：目標檔 `~/.codex/AGENTS.md`，內容＝`rules/core-rules.md`＋`rules/adapter-codex.md`。
- 兩個都有就各自處理、各自問、各自備份。目標檔不存在時，預覽要寫明「將新建此檔」。

### 2. 預覽並詢問

1. 讀現有目標檔（只讀）。
2. 檢查是否已有標記段 `<!-- agent-operating-rules:start` … `<!-- agent-operating-rules:end -->`：
   - 沒有：預覽「將在檔尾新增」的完整內容。
   - 有：預覽「將替換的舊段」與「新段」的差異，並寫出舊版號與新版號。
3. 檢查現有內容是否和規範衝突（例如已有不同的刪除規則或回覆格式），有就列在預覽裡，提醒你標記段外的舊規則不會被改動。
4. 用原生選項卡片問：「寫入（建議）」／「先不寫」。Claude Code 用 `AskUserQuestion`；Codex 用介面的選項提示，沒有才用文字附編號選項。

### 3. 你不同意

不寫任何檔，不建備份。回覆一句：之後要裝再說「安裝代理工作規範」即可。

### 4. 你同意後寫入

1. 先備份原檔成 `<檔名>.bak-<YYYYMMDD-HHmm>`（同資料夾）。原檔不存在就不用備份，但要記下「原本沒有這個檔」。
2. 把內容包在標記之間寫入：

   ```markdown
   <!-- agent-operating-rules:start v1.0.0 -->
   （core-rules.md 全文）

   （對應 adapter 全文）
   <!-- agent-operating-rules:end -->
   ```

3. 已有標記段（升級）：只替換 start 到 end 之間（含兩行標記本身），標記外的內容一個字都不動。
4. 沒有標記段：附加在檔尾，前面空一行。

### 5. 讀回確認

- 重新讀目標檔，確認 start 與 end 標記各只出現一次、版號正確、中間內容與規範檔一致。
- 把目標檔去掉標記段後，和備份檔去掉舊標記段後比對，必須完全相同（證明標記外沒被動到）。
- 任何一項不符：用備份覆蓋回去，回報失敗原因，不重試第二次。

### 6. 告訴你怎麼回滾

- 整檔還原：用 `<檔名>.bak-<YYYYMMDD-HHmm>` 覆蓋目標檔。
- 只移除規範：刪掉 start 到 end 之間（含兩行標記）。
- 原本沒有這個檔：把新建的檔移進垃圾桶。

### 禁止事項

- 不得在你同意前寫入任何檔。
- 不得修改權限設定、hook、settings 檔或任何標記段以外的內容。
- 不得連網、不得下載、不得執行任何程式。
- 不得自動排程重新安裝或自動升級。

## 安裝後建議

- 在每個專案根目錄放 `TASK_HANDOFF.md`（範本 `templates/TASK_HANDOFF.md`）。
- 有排程任務的專案加 `docs/待決策佇列.md`（範本 `templates/待決策佇列.md`），並在專案設定檔寫明「開工先讀待決策佇列」。
- `<決策者>`、`<門檻>` 這類佔位符可以在全域設定的標記段外另寫一行說明，例如「決策者＝我本人」，不要直接改標記段，升級時才不會被覆蓋。

## 規範背後的教訓

這些規則都是真的出過事才補上的：

1. **交接檔把當天結果寫得像指令**：「本輪只讀不改」被下一輪當成規則，任務因此被跳過。交接檔只寫事實與日期。
2. **備份檔放在公開目錄**：網站上的 `.bak` 與公開庫裡的備份都能直接下載，等於原始碼外流。備份放在公開範圍外。
3. **長輪詢的常駐程式卡死而且不會喊**：要有上限、要有人看得到的失敗訊息。
4. **為了塞進大小上限縮短規則，順手刪掉別人的規則**：檢查只看大小時照樣通過。改前後一定比對差異。
5. **只算新開的執行者、不算退修重啟的**：同時跑的執行者超過上限。退修也佔名額。
6. **卡片被拒一次就改用文字問**：對方在手機上看不到文字問句。被拒不等於不要卡片。
7. **審查通過就當驗收完成**：功能在正式環境根本沒跑過。驗收一定要實際跑一次。

## 升級

規範改版時，版號寫在 start 標記上。重新執行安裝流程即可：會偵測到舊標記段、預覽差異、問過才替換。
