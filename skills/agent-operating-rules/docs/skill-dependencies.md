# 其他 skill 怎麼依賴本規範

`agent-operating-rules` 是基礎規範：交接檔、待決策佇列、決策卡片、核准範圍、執行與審查分離、正式環境驗收。其他 skill 只要用到這些機制，就不必各自重寫一份，標示「建議先安裝」即可。

## 標示寫法

在依賴它的 skill 的 `SKILL.md` 標題下方加一行：

```markdown
建議先安裝 `agent-operating-rules`（代理工作規範），本 skill 的待決策佇列、決策卡片與驗收規則都依它。
```

原則：

- 只寫「建議先安裝」，不寫成硬性前置條件；沒裝也要能用，只是少了共用的交接與驗收習慣。
- 依賴的 skill 不要把規範內容整段抄進去，避免兩份規則日後不一致；需要時寫「依 agent-operating-rules 的○○段」。
- 規範升級（標記段版本號變了）時，依賴它的 skill 不用跟著改，除非用到的段落名稱改了。

## 與廣告類 skill 的互動

### meta-ads-optimize-monitor（廣告監控與優化）

- 排程遇到超出自動規則、要人取捨的事（例如加預算超過上限、要不要重建活動），追加一行到專案 `docs/待決策佇列.md`，格式照本規範。
- 換主對話或其他對話在該專案開工時，先讀佇列「待決」的行，再看排程最近幾輪結果。
- 要決策者決定的事用原生選項卡片問，建議項放第一個並標「（建議）」。
- 改了監控程式或儀表板，依本規範交另一個代理唯讀審查，並在正式環境實際跑一次排程才算驗收。
- 追蹤完整度優先：平台事件明顯少於網站實際數時，先修追蹤再做優化。

### meta-funnel-retargeting（全方位內容＋直效轉換廣告）

- 建完的活動一律是暫停草稿；要不要開始投放、預算多少，用決策卡片問決策者。
- 建置過程寫專案 `TASK_HANDOFF.md` 與待決策佇列，換代理接手時照本規範記錄接手者與範圍。
- 像素與轉換 API 的設定改動，以平台實際收到事件為驗收證據；需要真實付款才能觸發的事件，寫「已上線，功能實測待真實訂單」。

## 安裝順序建議

1. 先裝 `agent-operating-rules`，把規範寫進全域設定（安裝時會先預覽、經你同意才寫）。
2. 再裝依賴它的 skill。
3. 在專案資料夾建立 `TASK_HANDOFF.md` 與 `docs/待決策佇列.md`（範本在本 skill 的 `templates/`）。
