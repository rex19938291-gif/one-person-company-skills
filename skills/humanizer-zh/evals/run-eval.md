# 評測流程

## 最小回歸

在乾淨工作階段讀 `SKILL.md`、相關 `references/` 與 `evals/benchmark.md`，逐條處理：

- SF：輸出改寫與一句理由。
- SNF：輸出「放行」與一句理由。
- 格式：`用例｜判定｜結果／理由`。

人工核對三件事：命中或放行、保護內容零漂移、不換湯不換藥。

## 發版前交叉評測

1. 改寫端載入 skill，處理全部用例。
2. 判分端只看原文、預期與改寫結果，不載入改寫端結論。
3. SNF 任何非必要改寫記失敗；有爭議時人工終判。
4. 記錄模型、日期、SF 命中率、SNF 誤殺率、保護內容漂移與失敗案例。

不得用真實客戶資料、未脫敏引文或敏感內容建立評測。
