# Meta 廣告監控與優化

## 這個 skill 在解決什麼

廣告開跑之後，真正花錢的是「沒人看著的時間」：成效好的組合中午就把預算花完、成本變高的素材繼續燒錢、名額已滿還在收單。這套流程讓代理在固定規則內自己處理日常調整，把需要取捨的事交給決策者，並讓所有人隨時打開同一個儀表板看到最新數字。

它是從一個講座招生專案兩週的實戰沉澱出來的，但**規則的「形狀」可以共用，數字與策略不能照搬**。每個專案的目標、預算、受眾、粉專與素材策略都不同，套用前一定先讀該專案自己的紀錄。

## 鐵則

1. **先讀本專案、再規劃、確認後才執行。** 不得把另一個專案的策略、門檻或素材做法直接套過來。第 0 步沒做完，不得建立任何排程或改任何廣告。
2. **數字找不到紀錄就問，不猜。** 目標筆數、總預算、每筆成本上限、硬上限、結束日，任何一個沒有書面依據就列為「待決策者決定」，排程先以「只監控不動作」模式運作。
3. **加總預算、刪除、金流、憑證與權限、對外送出（含對客戶可見處）一律由決策者決定。** 排程只能做專案設定檔裡寫明、決策者確認過的動作。
4. **每次調整幅度 ≤20%**（加或減都一樣），一天一次為原則；盤中加預算另有條件（見 references/03）。
5. **結果只認指定的 action_type、以網站實收為準**：平台與網站對不上時自己查網站，不問人；加預算前先交叉核對。
6. **改完一律讀回**（狀態、預算、updated_time、網頁實際內容），不採信工具或執行者自報。
7. **建立廣告只建暫停或草稿**，除非專案設定檔明寫可以直接上線的情境（例如「被拒才重建、同一集替換」）。
8. **專案專屬值只放專案設定檔**：帳號、組合、試算表、目標、門檻、通知方式都寫在設定檔，排程與本 skill 不寫死；需要主對話決定的事一律追加到待決策佇列，換主對話也接得上。
9. **先診斷哪一段、再動手。** 改素材主線、改報名頁、加總預算之前，先照 references/11 產出漏斗分段表與「最值得優化的一段」判讀；素材之間報名率差距大時先處理訊息對齊與預算分配，不先改頁面。
10. 回報用白話、結論先講，行銷活動用中文名稱，不用內部代號。

## 第 0 步交付給決策者確認的「規劃單」

一頁就好，順序固定：

1. **結論**：建議這個專案用哪一種模式（完整自動優化／只加不減／只監控與建議）與理由。
2. **本專案既有策略摘要**（引用來源檔與日期）：粉專與 IG 身分、漏斗分層、素材主線、到達頁、追蹤方式、過去裁示。
3. **現況數字**：近 7 天、近 3 天、今天的花費、結果數、每筆成本；投放中的活動與預算；審查狀態；近 7／30 天漏斗分段表與「最值得優化的一段」（references/11）。
4. **落差**：既有策略說要做、帳號裡還沒做的事（例如裁示改用新粉專但廣告仍掛舊粉專）。
5. **建議參數表**：每一個門檻寫「建議值、依據、可否自動執行」；沒有依據的寫「待決定」。
6. **排程清單**：名稱、頻率、模型、可做與不可做的動作、結束日。
7. **要決策者按的事**：逐條、可直接回覆。

決策者確認後，把確認內容寫進專案設定檔與專案交接檔，再進第 4 步建排程。
