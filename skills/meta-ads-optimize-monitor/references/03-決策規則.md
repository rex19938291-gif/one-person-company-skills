# 03 決策規則

## 零、結果數怎麼讀（所有規則的前提）

- **只認專案設定檔指定的 action_type，完全相等比對**。名單類常見是 `offsite_conversion.fb_pixel_lead`（沒有才用 `lead`）；自訂事件可能是 `offsite_conversion.fb_pixel_custom`。名稱「含有」lead 的其他項目一律不算，例如 `offsite_content_view_add_meta_leads` 其實是瀏覽內容——曾因用「包含 lead」比對，把 0 筆名單讀成 7 筆而誤加預算。
- **以網站實收為準，對不上不問人**：平台數字與網站不一致時，自己依序查名單試算表、名額／場次統計、網站表單筆數（只數筆數，不讀個資），以網站表單為最終依據；只有網站資料讀不到時才通報。
- **任何加預算前，先用網站實收交叉核對**今天的結果數與每筆成本；網站實收低於平台數字時，以網站為準重新判斷。

以下是規則的「形狀」。每條的數字、是否自動執行，都以專案設定檔與決策者確認為準。以 C 代表每筆成本上限。

## 一、盤中成效好加預算（操作排程每輪檢查）

目的：成效好的組合不要因為預算中午花完而斷掉。
只在白天時段動作（例如 08:00–21:59；晚上剩餘時間短，不加）。要**同時**符合：

- 今天花費 ≥ 目前每日預算的 85%；
- 今天結果 ≥3 筆，且今天每筆 ≤ 0.8C；
- 持續有進單：最近 3 小時有新結果（hourly 分段，或與上一輪紀錄比較）；
- 距該組合上次盤中加預算 ≥2 小時，且今天盤中加預算 <2 次。

加法：每日預算 ×1.2 四捨五入（**每次漲幅 ≤20%**）。上限任一條會超過就不加或只加到上限：單一組合防呆上限、總花費硬上限、名額全滿、決策者另訂的合計上限。
每次加都記錄原值→新值、今天花費／結果／每筆、最近進單時間，並在輸出第一行提醒主對話。

## 一之二、盤中煞車（操作排程每輪檢查）

目的：成效差的組合不要在下午繼續燒錢，等到隔天才處理。中午到晚上（例如 12:00–21:59）每輪檢查，要**同時**符合：

- 今天花費 ≥ 目前每日預算的 50%；
- 依**網站實收**算的今天每筆成本 > 煞車門檻（例如 1.6C；實收 0 筆時，花費達門檻就算）。

動作：該組合每日預算降 20%（設下限，例如 1.6C 或專案自訂）；每組每天最多一次；當天有盤中加預算的，先撤回到加之前的數字。隔天由每日結算決定是否回升（每次 ≤20%）。

## 二、每日結算（每天固定時間後第一輪做一次；需要取捨，交判斷力較強的模型）

依序判斷，每個組合各自判斷，每個動作寫數字與原因：

1. 累計花費 ≥ 硬上限 → 暫停，通知決策者。
2. 連續 5 個完整日每筆 > 1.6C（或花費 ≥4C 仍 0 筆）→ 暫停，請決策者決定，不自行再開。
3. 昨天有盤中加預算：昨天整天每筆 ≤ C → 維持；> C → 降 20%，一天一次，直到回到加之前的數字。
4. 近 3 日 ≥6 筆且每筆 ≤ 0.8C → 每日預算 +20%（距上次結算加預算滿 3 天；受防呆上限限制）。
5. 近 3 日每筆 > 1.3C（且花費夠多）→ **先處理素材**：投放中的廣告最多暫停 2 則（先關「花費 ≥1.2C 仍 0 筆」，其次每筆最高）；每集或每主題至少留 1 則、整體至少留 4 則。沒有可關的素材、且距上次關素材滿 3 天仍偏高 → 才降預算 20%（設下限）。
6. 合計上限只在「昨天合併每筆 > C」時套用，超過先降最大的組合，每次 ≤20%、一天一次。
7. 素材開回：被暫停的廣告，若其他投放中廣告每筆連續 2 天高於它，或已暫停滿 3 天，一次只開回 1 則（不改內容），讀回確認。
8. 其他 → 維持不動，寫原因。沒有動作也記一列「維持不動」與判斷數字。

## 三、素材：缺集才重建、成效差才換文案

- **缺集才重建**：同一集或同一主題沒有任何投放中、審查中的版本，最新版本被拒，才重建；該集已有通過的版本，其他版本被拒一律不重建、不申訴。每集每天重建次數設上限。
- **換字規則**：只換最可能觸發審查的詞，換成同樣具體、意思相同的說法；分層換（第 1 層換最重的詞 → 第 2 層 → 第 3 層 → 第 4 層換圖），用完仍被拒就停，請決策者決定。
- **賣點不可模糊**：數字、案例、職業、價差口徑、核心承諾不得刪改或變含糊。換完自己讀一遍，覺得賣點變模糊就不建，記錄並請決策者決定。換字稿建立前交另一個唯讀審查者逐條比對。
- **成效差才換新文案**：單則廣告累計花費 ≥ C、曝光 ≥300、結果 0 → 為該集上新版本（每則廣告只觸發一次、每集每天最多 2 次）；該集已有另一則表現好的就不換。
- **舊版退場**：新版通過且開始正常投放（曝光 ≥200 或花費 ≥ 一小段）後，暫停同集較早的舊版；舊版本身表現好就保留。
- **申訴過仍被拒超過 48 小時**：暫停（不刪除）。
- 命名帶集數與版本（例如「EP03｜轉換-v2換字版」），版面一句一行、段落不超過 4 行。

## 四、名額與場次

- 平常只讀「場次人數」資料（已扣測試）；某場第一次到 80% 名額 → 通知；≥ 名額 → 回網站確認實際筆數 ≥ 名額才下架。
- 下架：先備份表單欄位原文 → 只移除該場選項 → 讀回選項數少 1、其他不變 → 清到達頁快取 → 抓到達頁原始碼確認該場文字已消失、其他場仍在 → 記錄並通知。剩 0 個選項時不移除，改走全部額滿。
- 全部額滿或已過期 → 暫停轉換活動並通知；表單選項不清空。
- 不重新上架、不刪報名資料、不改頁面文案；同一事件只記一次。

## 五、共通

- 每個動作都讀回確認；工具失敗等 30 秒重試一次，第二次失敗就停止該步並如實記錄。
- 規則沒寫到、需要取捨 → 不猜，記錄並在輸出第一行寫「需要主對話注意」。
- 停損程式等其他自動程式的動作只讀、只記錄，不去改它。
