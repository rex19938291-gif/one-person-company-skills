# 05 儀表板與通知

## 儀表板：一個網址、多個專案分頁

- 一個免登入、noindex 的靜態網站（例如 Cloudflare Workers 靜態資產），頁首有專案分頁；`?p=<專案代號>` 直接開某專案，沒帶參數開預設專案，手動切過記住上次選擇。
- 每個專案一份資料檔（`data/<專案代號>.json`），由該專案的操作排程每輪匯出；專案清單放 `projects.json`。**新增專案＝加一筆專案清單＋一份匯出設定，不改前端程式。**
- 部署永遠上傳整個資料夾，所以各專案排程誰先誰後都不會蓋掉別人的資料；部署用鎖，拿不到鎖時等一下（例如 90 秒）再放棄，避免同一分鐘撞到永遠跳過。
- 目標未定的欄位顯示「待定」，不自己填數字。

### 每個專案頁面要有

花費、結果數、每筆成本、進度（對目標或對時間）、各活動與組合、各素材表、逐日趨勢，以及該專案的操作紀錄（加減預算、開關素材、重建、下架）。

### 公開前必查

- 資料檔不含帳號編號、廣告與貼文編號、權杖、個資（姓名、電話、Email）、內部路徑、代理或模型名稱。
- 匯出時用替換表把內部代號換成中文名稱。
- 備份檔不要放在要部署的資料夾（會被公開）。
- 每輪匯出失敗時線上維持上一版，連續失敗只通知第一次。
- 數字要能和平台直接查詢逐項對上（花費、曝光、點擊、結果）。

## 通知

- 只有需要人注意的事才通知：場次快滿、已下架、全部額滿、硬上限、儀表板連續更新失敗、需要決策的事。
- 通知文字開頭固定標籤（例如【<專案> 廣告回報】），方便手機分類。
- 送不出就在輸出寫「通知未送達」，不重試超過一次。
- 日常回報先送主對話統整，再由主對話決定送給決策者，避免一天十幾則。
