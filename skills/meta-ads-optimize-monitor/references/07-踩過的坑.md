# 07 踩過的坑

| 坑 | 症狀 | 下次先做什麼 |
|---|---|---|
| 把 A 專案的策略套到 B 專案 | 規則和該專案的目標、粉專、素材主線對不上 | 第 0 步先讀本專案策略與裁示，交規劃單確認後才執行 |
| 預算單位寫錯 | 210 元被寫成 21000 | 讀回原值與幣別；無小數幣別寫整數元，不乘 100；寫完讀回 |
| 官方連接器改動只進草稿 | 回 is_draft=true，正式物件沒變 | 讀草稿再發布（publish_as_active=false），用正式查詢讀回 |
| 草稿預設是「啟用」 | 一發布就開始花錢 | 建完立刻設暫停再讀回 |
| 改廣告組合受眾 | 底下所有廣告重新送審 | 受眾、版位、排除不放進排程可做的動作 |
| API 限流 | 80004／2446079 | 看回應標頭用量 ≥60 就暫停，照建議時間等待；第二次被擋就停手回報 |
| 兩支排程都能改廣告 | 互相覆蓋、重複加預算 | 改廣告的事只放操作排程，回報排程只讀 |
| 排程 SKILL.md 沒寫模型 | 每 10 分鐘都用最貴的模型 | 首部寫 `model:`，日常便宜模型、判斷交子代理 |
| 「唯讀」排程其實會寫入 | 背景跑的指令碰到寫入路徑 | 唯讀排程只給讀取工具，寫入一律放操作排程 |
| 備份檔放在公開資料夾 | 備份被一起部署公開 | 備份放部署資料夾之外 |
| 試算表只給唯讀權限的腳本服務 | 開檔失敗 | 用有權限的帳號匯出成資料檔，再給前端讀 |
| 報名數含測試資料 | 名額提早被判定額滿 | 統計來源先扣測試；下架前回網站數實際筆數 |
| 改網站補丁後沒對齊監控登記 | 網站監控一直報「需重測」 | 審查與實測通過後，最後一步更新補丁登記 |
| 自訂事件被歸在 fb_pixel_custom | 讀 lead 欄位一直是 0 | 盤點時找出真正的結果 action_type 寫進設定檔 |
| 用「包含 lead」比對名單 | `offsite_content_view_add_meta_leads`（瀏覽內容）被當名單，0 筆讀成 7 筆、誤加預算 | action_type 完全相等比對；加預算前與網站實收交叉核對 |
| 名單數對不上就停下來問人 | 排程卡住、決策延誤 | 自己依序查試算表、名額統計、網站表單筆數，以網站為準；網站讀不到才通報 |
| 改了程式裡的提醒文字，後台設定沒跟著變 | 後台看到的≠實際送出的 | 走「設定版本＋自動遷移」，見 references/08 |
| 互動型自訂受眾太小 | 「受眾範圍太小，無法使用」 | 互動受眾越早建越好；初期用廣泛或網站受眾 |
| 半天、名單少時用今天每筆判斷降預算 | 下午 1 筆時每筆看起來很貴就被盤中降，晚上多進 2 筆其實正常，好組合被砍又重置學習 | 0 筆且花費 ≥ 約 2C 才白天降；有名單就等晚上看全天（references/03 一之二）；每日結算用近 3 完整日合計 |
| 每日結算漏跑沒人發現 | 早上結算沒跑，預算停在前一天的數字一整個上午，下午才被主對話發現 | 中午前任何一輪發現沒有今天的結算列就補做並註明；過時限寫佇列（references/03 二） |
| 規則一條條疊加，舊句沒作廢 | 排程同時讀到「白天不調預算」與「碰上限就加」、兩個不同上限，判斷互相矛盾 | 新規則明寫取代哪一條、舊句標作廢、同一件事只留一個現行值；衝突時排程不取捨，寫待決策佇列（references/03 五） |
| 改簡訊文字只讀回設定 | 簡訊商受理、有訊息編號，幾分鐘後送達回報才退回「內容有錯誤」，名單沒收到 | 換字前先用核准的測試手機實測，看到「已送達手機」才換；避開「領取」＋連結這類詐騙常見寫法；換上後追下一封真實簡訊送達；批次補發每封間隔 ≥2 秒（references/08 四） |
| 網站廣告訪客混入平台審核機器 | 網站訪客比平台到頁多一倍，誤判「平台少記一半」、報名率被算成一半 | 先依國家、螢幕解析度、停留秒數、「暫停／被拒／點擊 0 的廣告也有訪客」排除機器與內部測試，新素材上線當天特別注意；查證前不下「平台少記」結論（references/11） |
| 送審用組合塞滿 | 平台每個組合最多 50 則廣告，拆解測試建不進去、整條重測卡住 | 同一暫停活動下照同設定新開送審組合；不封存、不刪舊廣告 |
| 新開組合少了地區管制聲明 | 鎖定台灣的組合建立失敗（「無台灣通用廣告聲明」） | 從既有組合讀 regional_regulated_categories 與受益人／付款人，原樣帶上 |
| 暫停活動裡的「活動已暫停」被當成還在審 | 審查早就通過，排程一直空等，修正素材沒進主組合 | 廣告本身開啟＋顯示活動已暫停＝已通過；審查中、處理中才是還在審 |
| 送審測試素材沒帶追蹤參數 | 通過後原樣進主組合，名單算不到是哪則廣告 | 建素材後讀回追蹤參數與 IG，缺就重建；進主組合前再讀一次 |
| 只改文案不改圖 | 圖上的「0 頭期」才是觸發字，改文案白送審 | 先拆圖測、文測找出是哪邊；換字規則對圖上的字一樣適用 |
| 儀表板每 10 分鐘部署一次 | Cloudflare 限流（code 10429），連續一小時部署失敗、線上停在舊版 | 資料照常每輪匯出，部署改每 30 分鐘一次；遇限流下一輪也跳過 |
| 讀不到被拒原因就盲改 | 換了 11 處字眼仍被拒，白白用掉送審額度 | 先到企業支援中心「禁止刊登的廣告」讀理由；金融類理由要降整則金融密度，不是只換字 |
