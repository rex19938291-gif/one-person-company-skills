# 09 換主對話接手與待決策佇列

長期跑的廣告監控一定會遇到「主對話上下文太長、要換新對話」。這套做法讓排程不依賴任何一個對話還開著，換誰接手都接得上。

## 一、待決策佇列（每個專案一份）

- 位置：專案資料夾 `docs/待決策佇列.md`（範本：`templates/待決策佇列.md`）。
- 排程遇到「需要主對話決定」的事，**除了寫在輸出第一行，一律在佇列檔尾追加一行**（只追加、不改舊行）：

  `- YYYY-MM-DD HH:mm｜問題｜建議｜理由與數字｜狀態：待決`

- 主對話（不管哪一個）每次開工先讀佇列，處理完在該行後面補 `→ 已處理：決定內容（日期時間）`。
- 佇列是唯一不會遺失的決策來源；通知只是提醒，送丟了也還在佇列裡。

## 二、交接檔固定段落「新主對話接手步驟」

在專案交接檔（例如 `TASK_HANDOFF.md`）放這一段（範本：`templates/交接檔接手段落.md`），內容固定六步：

1. 讀交接檔、待決策佇列（先處理「待決」）、代理的記憶檔。
2. 接收排程回報：對操作排程與回報排程各設「完成時通知」（Claude Code 是 `update_scheduled_task` 的 `notifyOnCompletion: true`）。完成通知通常只送給最後一個訂閱的對話，新對話設了就改送給它。
3. 規則正本位置：各排程的 SKILL.md 與專案設定檔；調整紀錄看紀錄表。
4. 決策方式：需要決策者決定一律用選項卡片；寫入外部服務由主對話或排程自己執行，子代理只寫文案與設定。
5. 收到排程「需要主對話決定」→ 判斷後處理，並在佇列補「→ 已處理」。
6. 每次開工先讀設定檔 `records.experience_log`（預設 `docs/經驗沉澱待同步.md`）的「待同步」列並同步：專案新經驗照 references/04 寫進排程、skill 與跨專案教訓；skill 版本差異則將新版適用規則寫進本專案各排程，保留專案門檻與編號，核對完成才更新 `project.skill_version_applied`、標「已同步」。尚未完成的列保留待同步，不把接手當完成。

## 三、可直接貼上的開場指示

`templates/新主對話開場指示.md` 是一段文字，開新對話時整段貼上送出即可。內容：照接手步驟做、唯讀確認現況（讀設定檔列出的組合今天的花費、結果、網站實收）、用一則白話訊息報到（目前狀態、接下來會自動發生的事、待決策者處理的事）。

## 四、什麼時候該換主對話

- 對話開始變慢、出現自動摘要、或代理開始混淆不同工作線的回報。
- 換之前：把現況、待辦、最新決定寫進交接檔與佇列；確認排程不依賴這個對話（規則都在 SKILL.md 與設定檔裡）。
