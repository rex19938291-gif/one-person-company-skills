# 10 專案設定檔填寫說明

每個專案一份設定檔（從 `templates/project-config.template.json` 複製，放在專案資料夾，例如 `config/ads-monitor.json`）。**排程 SKILL.md 只讀這份設定檔，不寫死任何帳號、編號、數字或人名**；換專案只要換設定檔。範例見 `templates/project-config.example-seminar.json`（編號已用佔位符）。

| 區塊 | 欄位 | 說明 | 找不到依據時 |
|---|---|---|---|
| project | mode | full_auto＝照規則自動加減；add_only＝只加不減；monitor_only＝只讀、記錄、建議 | 先用 monitor_only |
| project | end_date | 排程到期自動停用；長期投放填 null 並設每週檢討 | null |
| meta | result_action_type | 結果事件，**完全相等比對**，名稱含 lead 的其他項目不算 | 盤點時從實際 insights 找出 |
| meta | units | 要監控的組合（或活動）與角色：main 主組合、test 新素材測試組合 | — |
| site | signup_source | 網站實收的來源，用來交叉核對平台數字 | 沒有網站資料就不開自動加預算 |
| records | decision_queue | 待決策佇列位置，排程「需要主對話決定」一律追加 | 預設 docs/待決策佇列.md |
| goals | cost_cap_per_result | 每筆成本上限 C，多數門檻由它推算 | null＝不自動加減，只建議 |
| goals | total_budget／hard_cap | 總預算與硬上限（到了就暫停並通知） | null＝不設 |
| goals | roi_rule | 有成交資料的專案用「營收 ≥ 廣告費才加預算」這類條件 | null |
| thresholds | raise_*／brake_*／lower_pct | 盤中加預算、盤中煞車、降幅；每次加減 ≤20% 為原則 | 用範本預設，brake 預設關閉 |
| thresholds | insight | 主動洞察六項的門檻 | 用範本預設 |
| notify | channel | 通知方式，見 references/05「通知」 | queue_only |

填完後在專案交接檔記下「設定檔位置、確認日期、由誰確認」，任何門檻改動都要記錄原值與新值。
