## 四、網站端（WordPress + Pixel Cat）

- Pixel Cat 原生的 Purchase 只要打開訂單感謝頁就送，不看付款狀態，零卡審核中、未付款都會被算成購買。
- 它的「轉換 API」其實是瀏覽器觸發後由網站轉送，瀏覽器的像素被擋時，網站端那筆也不會送。
- 解法：在 sandbox 寫一支程式，移除 `fca_pc_purchase`。訂單第一次變成處理中或已完成時，用背景工作由伺服器送 Purchase；感謝頁只有已付款才用 `trackSingle` 送；兩邊的 event_id 都用 `wc_purchase_<訂單號>`。範本：該專案 sandbox 裡的購買事件程式（檔名記在專案交接檔），經 Codex 六輪審查。
- 同一個網站只能有一支程式處理感謝頁的 Purchase，別的工作線不要另加。
- Pixel Cat 改設定要按兩次儲存：先按像素視窗的「Save」，再按頁面最下方的整頁「Save」。
- 驗證網站端事件：在伺服器用 `http_api_debug` 抓 Meta 的回應，看 `events_received`。不要只看 admin-ajax 回 200，那個不管成功與否都回 200。

## 五、舊版 API 寫法（保留參考）

`<作者本機工具，未隨技能附上>` 的 `call(path, params, method, data)` 會回傳 `(status, json)`，寫入要 `--yes`，輸出經 `scrub()` 遮罩。

盤點粉專貼文：

```python
import sys; sys.path.insert(0, "<你的本機路徑>")
import social
tok = social.page_token(PAGE_ID)
d = social.pcall(tok, f"{PAGE_ID}/posts", {"fields": "id,created_time,message,permalink_url", "limit": "50"})
```

用貼文建素材：`POST act_<帳戶>/adcreatives`，帶 `object_story_id=<page_id>_<post_id>`、`instagram_user_id`；建廣告時 `status=PAUSED`。

## 六、每月例行

1. 抓當月新貼文，對照內容類型，決定放進哪個活動。
2. 新增廣告（暫停），不動既有廣告，讓舊貼文的互動繼續累積。
3. 查每個自訂受眾的人數，過門檻的回報「可以開了」。
4. 素材疲勞時暫停舊廣告，不要刪。
5. 在專案台帳記一行，包含失敗。
