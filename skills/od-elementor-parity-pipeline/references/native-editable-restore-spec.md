# 網站還原到 WordPress：業主可編輯規格（2026-10-17 B 客戶定案，之後所有還原一律照做）

> 由 `SKILL.md` 的「業主可編輯還原規格」節載入。你 2026-10-18 指示：前端 UI 還原到 WordPress，一律比照B 客戶這次的規格執行，
> 不能只還原樣式；業主要能在 Elementor 面板換文字、換圖片、改連結。頁首頁尾、按鈕、圖片尤其不能遺漏。

## 二、架構：原生元件存值＋樣板組回原網頁結構

還原頁的動畫、手機版程式依賴原本的 DOM，直接換成 Elementor 原生輸出會壞。做法：

1. **編輯值放原生元件設定**（title、editor、text、link、image、tabs、icon_list、shortcode）。
2. **原網頁碼樣板**以 base64 存在元件的 Pro 自訂屬性 `data-zbt`，可編輯處換成佔位：`{{title}}`、`{{link}}`、`{{editor}}`；重複項目用 `{{@rows 欄位}}…{{/rows}}`，列內 `{{.tab_title}}`、`{{.text}}`、`{{.#zh}}`（一二三序號）；第一列樣式不同用 `第一列{{@rest}}其他列`。照片另存 `data-zbi`＝原附件 ID。
3. **前台組回**：站點外掛在 `elementor/frontend/before_render`（ob_start，依元件 spl_object_id 記錄層數）與 `after_render` 用目前設定值帶入樣板輸出。富文字只有一段就放回原 `<p>`；多段或含清單用 DOMDocument 解析最外層節點，最外層 p 套原開頭標籤、其他區塊原樣。帶入的內容先把 `{{` 換成記號、最後換回，避免被再次展開。連結擋不安全協定。照片沒換圖就輸出原網頁碼；換圖才改 src／srcset／alt（用回呼，值裡的 `$1` 不會被吃掉），清除照片就不輸出。組回出錯記錄並退回原輸出。
4. **轉換工具自我檢查**：每個元件「樣板＋設定值＝原網頁碼」，不相等就保留原網頁碼，不可硬轉。
5. 這些頁面若只印站點自己的樣式（不載 Elementor 前台樣式），業主新增的元件在前台會沒有樣式——交接要寫明。

## 三、編輯器預覽一致（最容易漏）

- Elementor 編輯畫面**不輸出容器與元件的 Pro 自訂屬性**（style、data-*），所以版面在預覽中會亂。
- 每頁（與頁首頁尾範本）的頁面設定「自訂 CSS」加一段只在 `.elementor-editor-active` 生效的規則：①通用相容層（拿掉容器預設方向／間距／內距／寬度、元件外層與內層 display:contents、字型顏色繼承）；②逐元素規則：以 `.elementor-element-<元素ID>` 帶入原本的行內樣式；問答、清單、附說明照片另產生對應規則。前台不印這段（要驗證 0 次出現）。
- **元素 ID 每份文件都不能重複**（頁首與頁面在同一個預覽裡，撞 ID 會互相套樣式）：亂數種子依文件 ID，並避開既有 ID。
- 站點外掛在 Elementor 預覽模式（用 `preview->is_preview_mode()` 判斷，不用網址參數）補載頁首樣式；編輯頁首頁尾範本時也載入全站樣式。
- 驗收：無頭 Chrome 開編輯器，用 `$e.run('document/elements/settings', …)` 改標題、連結、換照片，截圖看預覽即時更新；不存檔。

## 四、作業流程（照順序，每步驗完才下一步）

1. **抓線上最新資料**（不可用舊快照），伺服器上另存一份快照到 `wp-content/updraft/…`（.php 開頭 exit 或 updraft 底下），網址必須不是 200。
2. 轉換（`nconv.py`）＋自我檢查 → 產出各頁元素樹。
3. 建草稿副本（`mkdraft.py`：草稿、noindex、複製原頁所有 meta、寫入元素樹與編輯預覽 CSS，頁面設定一律 `wp_slash`）。
4. **前台逐行比對**：伺服器端以維護帳號暫時登入憑證渲染正式頁與草稿（`render-cmp.php`、`rcmp.py`、`rdiff.py`），只允許屬性先後、頁面身分（首頁／隱私權頁 body class）差異；憑證用完撤銷。注意：直接呼叫 `get_builder_content` 不會觸發組回，比對要用真正的頁面請求。
5. 編輯器實測（第三節）＋業主帳號實測後台入口與編輯器（不存檔、事後確認正式內容雜湊未變、沒有新的自動暫存）。
6. 外掛修改：先 Codex 新對話唯讀審查到 P0/P1 清零（P2 不擋）；同一機制連續卡關時改用可重複執行的簡化做法，不要無限補強。部署前後各抓一次 8 頁未快取輸出逐字比對；需要 你 本人按同意。
7. 切換前：業主修改比對（`owner_diff.py`，基準是**上次寫入的版本**，不是更早的備份）；有差異的頁先不切，交驗收方決定。
8. 備份（`backup.php`：資料＋頁面設定＋存在旗標＋雜湊，讀回核對）→ 逐頁切換（`apply.php`：先全檢查再寫入、頁面設定 wp_slash、逐值核對、**更新頁面修改時間**避免舊自動暫存被當成較新）→ 每頁比對 → 頁首頁尾最後換 → 清快取＋預熱。
9. 驗收四通道：輸出比對、截圖親讀（電腦 1440／手機 390）、WebKit 六寬度（孤字與溢出 0，孤字用 `orphanfix.py` 加不斷行，注意不可包到整段長字造成溢出）、速度（手機首頁冷快取 2–3 輪對照基準、快取後各頁）。沒全過就用 `rollback.php` 還原（還原前整批驗證備份）。
10. 收尾：草稿改私人（不刪）、交接寫入可改／不可改清單與保留網頁碼清單、共用教訓。

## 五、踩過的坑（每條都實際發生過）

- 編輯畫面不輸出 Pro 自訂屬性 → 必須用逐元素編輯 CSS。
- 不同文件元素 ID 相同 → 頁首與頁面的編輯樣式互撞（標誌放大、選單重疊）。
- 切換只寫 meta、沒更新 post_modified → 舊自動暫存變「較新」，業主一開編輯器就被提示還原舊版。
- `update_post_meta` 會去反斜線 → 頁面設定寫回一律 `wp_slash`，還原要逐值核對資料與設定。
- WordPress `add_option` 不是原子鎖（同時新增會覆蓋）；需要互斥時用資料庫單次條件操作，或改成可重複執行的設計。
- 富文字多段用正規表示式拆會拆壞巢狀區塊 → 用 DOM 解析最外層。
- 結構化資料輸出沒加 `JSON_HEX_TAG` → 內容裡的 `</script>` 可提早結束標籤。
- 去標籤產生問答時要保留空行、區塊邊界換行，否則和原資料不一致。
- 孤字用不斷行修時，若包到外層長標籤會讓整段不換行而溢出畫面。
- WP Rocket 效能提示程式（wpr-beacon）會在清快取後出現在有快取的頁面，量速度時要辨識來源，不是改版造成。
- 會議或示範期間業主可能存檔（例如改了搜尋標題、頁面設定少了 hide_title），切換前一定先比對並保留業主的決定。
