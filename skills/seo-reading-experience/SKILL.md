# SEO 閱讀體驗優化

## 目的

把一篇已存在或新撰寫的繁體中文文章，整理成讀者能快速掃讀、理解並繼續閱讀的 SEO 內容。這個 skill 負責文章架構、標題關鍵字、段落留白與列表呈現；需要「去 AI 味」或台灣用語校正時，可再搭配 `speak-human-tw` 或 `humanizer-zh`，不可用結構優化取代事實核對。

## 預設規則你當次明確指定的架構、字數、關鍵字或版型優先。閱讀體驗優化是預設功能；SEO 關鍵字是選用功能，不可在你未提供關鍵字時自行假設或補上。

1. 保留事實、數字、日期、專名、連結、CTA、承諾、產品規格與原意。只為閱讀順序、標題、斷句與呈現方式調整，不為了 SEO 補造新事實。
2. 長文預設用 Why → What → How → How to do 的邏輯梳理：先說明為什麼重要，再解釋是什麼，接著說明如何規劃，最後提供可執行流程。這些英文只作為內部規劃標記；最終文章的 H2 必須改成自然的繁體中文，不得留下 `Why`、`What`、`How` 或 `How to do` 前綴，除非你當次明確要求保留英文。
3. 文章標題使用原生 H1；主要主題用 H2；細分問題、步驟與 FAQ 用 H3。Google Docs 交付時必須使用 `HEADING_1`、`HEADING_2`、`HEADING_3`、`NORMAL_TEXT`，不得只用粗體或放大字級假裝標題。
4. SEO 關鍵字只有在你提供或明確要求時才啟用；啟用前先詢問兩組資料：「核心／目標關鍵字有哪些？」以及「長尾關鍵字有哪些？」。若你只要求閱讀體驗優化，先做結構、分段、留白與列表，不自行改寫標題加入關鍵字。
5. SEO 模式啟用後，關鍵字要放在讀者真正會搜尋的標題與問題位置，不重複堆疊、不破壞語氣。核心關鍵字優先放 H1／H2；長尾關鍵字放對應意圖的 H2／H3、步驟標題與 FAQ。
6. SEO 模式啟用後，FAQ 每個問題標題都要包含一個指定長尾關鍵字，優先使用接近原搜尋句的自然問法；未啟用 SEO 時，不強制 FAQ 使用關鍵字。

## 執行流程

### 1. 盤點來源與 SEO 選用狀態

- 讀完全文並確認文章邊界、現有 H1／H2／H3、清單、表格、連結與 CTA。
- 先判斷你是否明確要求 SEO 或提供關鍵字。沒有明確要求時，將 SEO 標記為「未啟用」，不自行產生關鍵字。
- 若你要求 SEO，先停在取資料階段，詢問：核心／目標關鍵字有哪些？長尾關鍵字有哪些？收到後才建立對應：核心關鍵字 → 文章主題與 H2；長尾關鍵字 → 具體問題、步驟、選購與 FAQ。
- 先記錄必須保留的數字、專名、連結、產品名稱與承諾，之後逐項核對。

### 2. 重排文章骨架

優先採用以下順序，標題文字依文章主題改寫。以下英文是工作用標記，不得直接輸出到最終 H2：

- `Why` → 使用自然中文 H2 說明讀者為什麼需要處理這個問題、現在不處理會遇到什麼情況。
- `What` → 使用自然中文 H2 解釋核心概念、設備、方法或判斷標準。
- `How` → 使用自然中文 H2 說明如何規劃、選擇、配置與避免常見錯誤。
- `How to do` → 使用自然中文 H2 說明依序可執行的步驟、檢查清單與後續調整方式。

每個 H2 下先放結論或場景，再放理由與細節。不要為了湊架構重複同一段內容；原文已有清楚順序時，只做必要的標題與段落整理。

### 3. （選用）套用關鍵字與 FAQ 命名

只有 SEO 模式啟用時執行本節：

- H1 放一次主要主題或核心關鍵字，讀起來要像文章標題，不要拼接關鍵字清單。
- H2 放核心關鍵字與較大的搜尋意圖，例如「核心主題與使用情境」或「自動化流程怎麼規劃」。
- H3 放具體操作與長尾搜尋意圖，例如「產品怎麼選？」、「尺寸怎麼算？」或「自動控制可以嗎？」；實際文字以當次提供的關鍵字為準。
- FAQ 的每一題都要用當次指定的長尾關鍵字命名，格式可採「[長尾關鍵字]＋自然問句」，不可只寫「常見問題」或「Q&A」。
- 關鍵字若硬放會造成不自然，改放到更合適的同層標題、FAQ 或步驟，不在正文反覆重複。

### 4. 依語氣分段與句號留白

- 以完整語意而不是固定字數切段；一段只處理一個主要意思。
- 長段落遇到結論轉原因、原因轉做法、場景轉例子或語氣明顯轉折時換段。
- 句號、問號、驚嘆號後，若下一句已是新的語意，就換成新段；一般正文段落之間保留一個空白行。這個空白行是獨立的空段，不要用多個半形空格代替。
- 連接詞（例如「但」「因此」「如果」「同時」「尤其」「這類」）可作為候選分段點，但不要把同一個短句拆得支離破碎。
- 以約 120～160 個可讀字元作為長段落警戒值，不是硬性截斷規則；完整短句與必要的上下文優先。
- 標題後直接接正文；項目符號彼此連續，不在同一個清單項目之間插入空白項目。

### 5. 把列舉改成原生列表或表格

只要正文出現「包含幾個部分」「包括 A、B、C」「需要確認 A、B、C」「第一、第二、第三」或可獨立閱讀的條件清單，就優先整理成一項一意的列表：

- 支援、特性、條件、風險與檢查項目使用項目符號。
- 有明確先後順序、執行流程或步驟使用編號清單。
- 每個項目用平行句型，必要時用「名稱：說明」格式；不要把整段複合句塞進一個 bullet。
- 三個以上項目若共享相同欄位（例如「條件／影響／建議」），表格比長串 bullet 更容易比較時，才使用原生表格；不要為了形式把一般敘述硬塞進表格。
- Google Docs 交付必須使用真正的 `createParagraphBullets` 或原生表格；不得把 `•`、`-`、`1.` 當成假列表留在正文中。
- 列表前保留一句簡短引導語，列表後再接必要的結論或限制，避免讀者看不出清單用途。

### 6. 保留連結與 CTA

保留原有連結的可見文字與 URL 順序；不要因重排而遺失連結。CTA 保留品牌名稱、服務內容、行動邀請與承諾條件，必要時獨立成 H3 與短段落，但不改成誇大保證。

## 品質檢查

交付前逐項確認：

- 正文的數字、專名、連結、CTA、承諾與原意仍在；沒有憑空新增事實。
- H1／H2／H3 層級正確；只有 SEO 模式啟用時，才核對核心關鍵字、長尾關鍵字與 FAQ 命名。
- 最終輸出的 H2 不含 `Why`、`What`、`How`、`How to do` 英文前綴；除非你明確要求英文標題。
- SEO 模式啟用時，FAQ 每一題的 H3 都含指定長尾關鍵字；未啟用時，不因缺少關鍵字而改動 FAQ。
- 長段落已依語意適度拆開，正文段落之間有一個空白行；沒有多餘空白 bullet。
- 列舉已轉成一項一意的原生清單，步驟使用正確順序；共享欄位的項目才使用表格。
- 原生 Google Docs 讀回能看到 `HEADING_1`、`HEADING_2`、`HEADING_3`、`NORMAL_TEXT`、清單與連結。
- 另外回報重編前後的字數差異；若增加主要來自標題、清單標籤或分段，不要把排版變化誤報成新增內容。

## 輸出方式

先產出可審閱的重編全文，再依你要求建立 Google Docs、Markdown 或其他格式。若是 Google Docs，多篇文章依既定規則使用同層文件分頁，一頁一篇；單篇文章則保持單一分頁並套用原生段落樣式。
