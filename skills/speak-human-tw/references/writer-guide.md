# 寫手與編輯完整使用說明

## 生成邏輯

本包的改寫主體是 `speak-human-tw`；`seo-reading-experience` 的語義分段原則已整合，不需要另裝它，更不需要把多套 humanizer 連續跑一遍。Google Docs／Sheets 工具只負責取得來源與交付，需由執行環境另行連接。

每篇按以下順序處理：

1. 讀取任務、最新原稿及指定品牌資料庫，確認文章對象、目的、關鍵字與交付方式。不能用公開 skill 的範例代替品牌事實。
2. 列出不能漂移的事實、數字、專名、引文、關鍵字、連結與承諾。需要更正的品牌事實以明確確認為準。
3. 去除空話、模板化開場、重複結論、誇大語氣和不自然用語；保留作者的觀點、故事及資訊量，不補造資歷。
4. 調整主標題語序與語意完整性；H2 分組、H3 直述該節要解決的問題。保留必要順序及關鍵字，不機械加詞或縮短。
5. 按語義分段；同一意思的幾句話同段，轉論點再換段，段間留白。Google Docs 以原生段落與段後間距呈現，不逐句換行。
6. 以品牌資料核對 CTA 的正式名稱、網址、邀請和附帶內容，並保留原生超連結。
7. 交付完整全文與要求的替換前後對照表；核對表格右欄與正文一致。只改排版另行說明，不列為文字改寫。
8. 若收到人工定稿，與上一交付版比對；確認差異後，通用規則回饋 skill，確認的品牌事實回到資料庫。此步按任務執行，不是自動監看。

## 使用方式

按 README 安裝整個資料夾；在支援 skill 的工具中指定 `speak-human-tw`。希望直接取得改寫版時，指令加上「這次直接套用，不用先列清單等確認」；只想審稿則說「先列問題，不要改寫」。

有品牌背景更新或現有定稿回饋時，同時提供品牌資料庫連結和新舊稿。權限不足時，先取得可讀取的授權或經確認的文字副本，不要把私人資料庫改成公開分享。

## LINE 派稿範本

下面是給寫手的派稿訊息，不是對消費者發布的文案。替換括號內容後直接貼到 LINE；網址用完整獨立一行，段落間空一行，不使用 Markdown 超連結或表格。

```text
【文章潤稿與交付規格】

請使用「說人話」speak-human-tw，這次直接套用，不用先列清單等確認。

Skill 與安裝說明：
〔完整 GitHub 網址〕

本次文章：
〔文章標題〕
〔完整原稿網址〕

品牌資料庫：
〔完整資料庫網址〕
指定分頁／欄位：〔填入〕
請每次先讀最新資料，再引用品牌背景與報名資訊。

寫作要求：
保留事實、數字、品牌名、關鍵字、引文及承諾，刪除空泛與誇大的說法，不新增經歷或服務。
標題語序自然且意思完整；H2 清楚分組，H3 直接說明重點，保留必要的步驟順序。
同一意思留在同一段，換論點再分段；段落間留白，不逐句換行。

結尾邀請：
連結文字：〔正式名稱〕
目標網址：〔完整網址〕
邀請內容與附帶承諾：〔依品牌資料填入〕

交付方式：
每篇一份 Google Doc，保留原稿，最上方放替換前／替換後對照表，再接完整正文。請核對表格右欄與正文、標題層級、分段及超連結。
交稿時提供完整網址，以及尚待確認的事項；沒有就寫「無」。
```

## LINE 交稿範本

```text
【文章交稿】

文章：〔標題〕
〔完整 Google Doc 網址〕

本次調整：
〔只列實際完成的標題、用詞與分段修改〕

品牌資料：
〔資料庫名稱／分頁／讀取日期〕

已核對：
正文與對照表一致，事實與數字保留，結尾邀請名稱及網址正確。

待確認事項：
〔問題與所在段落；沒有就寫「無」〕
```

LINE 的空行是訊息排版，不等於文章每句都換行。文章維持語義段落。交稿範本的「已核對」只有做完才能填入；若未建立 Google Doc，改為說明實際交付格式。
