# SEO 寫手 SEO 審稿（文章初稿驗收）

## 定位

寫手交稿 → **本 skill 排查到 60 分及格** → 才轉給業主。

業主只該做「資訊正確性」與「對消費者口徑一致」的審查。閱讀體驗、文章邏輯、圖文一致性這三件事，是我們自己要先掃乾淨的，不能丟給業主逐篇找。

與其他 skill 的分工：

- `seo-reading-experience`：**怎麼寫好**（正向排版與改寫工具）。本 skill 不取代它。
- `humanizer-zh`：去 AI 味。
- 本 skill：**收稿驗收**，只判定與列出退回項，不動寫手的稿。

## 這套標準的來源

規則全部來自兩份實務文件，不是通則：

1. 給寫手的文章修改建議（逐篇點出的最佳化項目）
2. 與寫手的會議共識（2026-08-12）——哪些閱讀體驗建議會撞到 SEO，寫手用專業判斷取捨後的結論

**核心原則：A 組是寫手的專業領域，排查時不得要求修改；B、C、D 組是我們的及格線，必須達成。**

## 執行流程

1. 取得預覽連結（通常是 `?p=NNNNN&preview=1&_ppp=xxxx` 或已上線網址）。
2. 用 `scripts/extract.py` 抓 HTML 到 scratchpad，抽出標題結構、段落、表格、圖片序列與 alt。**不要把整份 HTML 讀進對話**。
3. 資訊圖必須**逐張看過**，把圖上的文字讀出來。下載後先 `sips -Z 1100` 縮圖再看，一次一張。只憑 alt 判斷不算檢查過——alt 寫 7 項而圖只畫 4 項的情況實際發生過。
4. 依 A/B/C/D 四組逐項核對。
5. 依「輸出格式」產出修改建議（見最後一節）。

## A 組｜SEO 底線（不得要求修改，違反者是我方誤判）

| 代號 | 規則 | 理由 |
|---|---|---|
| A1 | H1 主題關鍵字必須在**前三個 H2 內至少出現一次**。不得為了閱讀順序，把含主題詞的段落往後搬 | 前三個 H2 決定 Google 對整篇主題的判讀；搬走會被誤判成另一個主題 |
| A2 | H2 命名以關鍵字規劃為主。要改順序或補邏輯，只能改寫**承接句**，不動 H2 的關鍵字 | 同上 |
| A3 | **不得**要求加 highlight、色塊、quote 強調框、重點標記 | 寫手認定這是 AI 文章特徵，有被判定為 AI 產出的風險。要強調改用 B1 的結尾列點 |
| A4 | 標題盡量少標點符號 | 寫手文風規則 |
| A5 | 列點與表格可放心使用 | 較容易被搜尋引擎與 AI 收錄（GEO） |
| A6 | 口語化長句、輕微贅字，屬作者文風，**不列為缺失** | 會議已確認寫手刻意用口語、減少文言 |

排查時若某個閱讀體驗問題只能靠違反 A 組來解，**寫成「已知取捨，不退回」並附理由**，不要列進退回清單。

## B 組｜閱讀體驗必達項（及格線，每項都要打勾）

| 代號 | 檢查項 | 判定標準 |
|---|---|---|
| B1 | **結尾總結** | 最後一節必須回扣開頭提出的核心問題，且含 3–7 點精簡列點。只有純文字段落＝不及格 |
| B2 | **用詞一套到底** | 同一組重點在 H3、內文表格、資訊圖、結尾總結之間，必須用**同一套詞**、同樣數量。出現兩套以上＝退回 |
| B3 | **無重複段落** | 同一論點不得在兩節重複闡述。重複者：刪除，或改寫成「除了前面的 X，還要知道 Y」的承接 |
| B4 | **節與節有承接** | 每個 H2 開頭要有一句把前一節接起來的話，讀者不會覺得跳段 |
| B5 | **專有名詞首見即解釋** | 來電復歸、中性線、網關、常電這類詞，第一次出現就要用一句白話說明（不必用強調框，行文帶過即可） |
| B6 | **標題所問必被正面回答** | H2 問「廠商不見了怎麼辦」，內文就要正面回答遇到時怎麼處理，不能只寫「事前如何預防」 |
| B7 | **表格欄位齊整** | 第一欄項目用詞長度與語意層級統一（例如統一四字）；不可出現「缺點」混在「使用限制」這種不同層級的標籤；不可用同一個詞解釋自己 |
| B8 | **商業立場到位** | 涉及風險議題時，要帶出正確做法與業主的優勢（例：原廠授權、台灣代理商保固、避免水貨；業主可整合多品牌且貨源來自總代理） |
| B9 | **錯別字** | 在／再、甚麼／什麼這類，逐句掃 |

## C 組｜圖片核對（每張資訊圖逐張過）

| 代號 | 檢查項 | 判定標準 |
|---|---|---|
| C1 | **數量對帳** | 圖上標「N 個重點」，就必須等於內文列點／H3 的數量。多一項少一項都退回 |
| C2 | **用詞對帳** | 圖上的項目名稱與 H3、表格、結尾總結同一套詞（與 B2 連動） |
| C3 | **立場對帳** | 圖上的建議不得與內文的優先順序或 FAQ 的結論相反 |
| C4 | **數值對帳** | 圖上每個數字（百分比、公升/日、年限）逐一回查內文 |
| C5 | **重複偵測** | 同一節不可同時放內容重疊的圖與表，圖必須比表多給東西 |
| C6 | **位置規則** | 總覽型資訊圖放**節首**（引言之後）不放節尾；同一篇文章所有資訊圖的擺放位置要一致；圖所在的 H2 底下要真的有對應段落 |
| C7 | **基本項** | alt 有寫且與圖上內容一致、檔名語意化、圖沒有跨篇誤用 |

## D 組｜致命錯誤（出現任一項，直接退回，不必往下算分）

- **D1 跨篇錯置**：某一節的內容整段屬於另一篇文章（實際發生過：選廠商篇的結尾放的是除濕篇的總結）
- **D2 圖文數量矛盾**：內文說 7 個重點，圖只顯示 4 個
- **D3 標題與內容完全不對應**
- **D4 事實／數字前後互相矛盾**

## 及格判定

- D 組任一項成立 → **不及格**，整篇退回。
- B 組 + C 組全部打勾 → **60 分及格**，可轉交業主做資訊審查。
- A 組的取捨項另外列成「已知取捨」附在報告，供對業主說明用。

## 輸出格式（固定，不要自創）

一篇一段，依這個結構寫，內容可直接複製進 Google Doc 交給寫手：

```
# <文章標題>

<文章連結>

## 修改建議

<退回項 1>
<退回項 2>
...
```

規則：

- 退回項**依嚴重度排序**：D 組致命錯誤最前，其次 B 組，再其次 C 組圖片項。
- 每一項要能單獨看懂：**在哪一節（用實際的 H2 編號與標題）、原文寫了什麼、該改成什麼**。不要只寫代號。
- H2 編號以文章實際的 H2 順序為準，不要沿用修改建議文件裡的提案大綱編號（兩者常常差一號）。
- 全部通過的項目不列出來，不寫「✅ 通過」那種清單。
- 排查過程的逐項打勾表留在自己手上備查，交出去的只有這份修改建議。

另外附一份**「已知取捨、不退回」**（A 組代號＋理由），這份不給寫手，是拿去跟業主解釋為什麼有些閱讀體驗建議不採納用的。

## 對業主的說明口徑

「閱讀體驗與文章邏輯我們已經先排查過，您這邊只需要確認資訊正確性，以及對外的說法是否與貴公司口徑一致。」

## 判例（2026-08 電商型客戶站 三篇）

- 圖只畫 2 個比較項、緊鄰的表格有 4 項 → C1 退回
- 圖寫「實體展間」列為必看重點，內文與 FAQ 都說「不一定要有展間」 → C3 退回
- 圖第 2 步寫「智能插座通電」，內文主張「原生智能控制比直接斷電更完整」 → C3 退回
- 同一組 7 個重點，圖／表用四字詞、H3 用問句、總結又一套 → B2 退回
- 結尾三段純文字、沒有列點 → B1 退回
- 「除濕自動化」不從第二節搬到第五節 → A1，已知取捨，不退回
- 開頭核心句不做 quote 色塊 → A3，已知取捨，不退回
- 口語長句不刪贅字 → A6，已知取捨，不退回
